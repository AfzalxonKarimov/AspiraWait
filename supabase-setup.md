# Supabase Setup Guide

## 1. Create a Supabase Project

1. Go to [supabase.com](https://supabase.com) and sign in (or create a free account).
2. Click **"New project"**.
3. Enter a **Name** (e.g., `Aspira Waitlist`).
4. Enter a secure **Database password** (save this — you won't see it again).
5. Select a **Region** close to your users.
6. Click **"Create new project"**. This takes 1–3 minutes.

## 2. Get Your Project Credentials

After the project is ready, go to **Project Settings → API** and copy:

- **Project URL** (looks like `https://[random-string].supabase.co`)
- **anon (public)** key

## 3. Create the Waitlist Table

In the Supabase SQL Editor, run this SQL:

```sql
-- Create the waitlist table
create table public.waitlist (
  id bigint generated by default as identity primary key,
  email varchar(254) not null unique,
  telegram_username varchar(100),
  created_at timestamp with time zone default now()
);

-- Index for fast lookups
create index waitlist_email_idx on public.waitlist (email);

-- Optional: Row Level Security (allows public inserts so the form can write)
alter table public.waitlist enable row level security;

create policy "Allow public insert"
  on public.waitlist
  for insert
  with check (true);

create policy "Allow public read"
  on public.waitlist
  for select
  using (true);
```

> **Note:** In a production app you'd lock down reads, but for a waitlist landing page, allowing anonymous inserts via the `anon` role is fine. The `unique` constraint on `email` prevents duplicates at the database level.

## 4. Wire Up in index.html

Replace these placeholder values in the JavaScript at the bottom of `index.html`:

```js
// Replace with your actual Supabase credentials
const SUPABASE_URL = 'https://your-project.supabase.co';
const SUPABASE_ANON_KEY = 'your-anon-key-here';
```

## 5. (Optional) Environment Variables

If you later deploy behind a build step (e.g., Next.js), store these as environment variables instead of hardcoding:

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
```

For the current plain-HTML approach, hardcoding the `anon` key is acceptable since it's already public by design.
